# RFC: UI Component Layer Strategy (Tailwind + shadcn Integration)

## Status
- Proposed

## Date
- 2026-03-13

## Owner
- Litria (solo)

## Summary
Define a layered UI component strategy that introduces Tailwind CSS as a utility layer and shadcn/ui as the source for interactive overlay primitives, while preserving Litria's existing hand-rolled CSS and glass-morphic visual identity. The strategy establishes clear boundaries between technologies and a decision framework for future component development.

## Problem
Litria's interactive UI chrome (modals, menus, popovers, context menus) is hand-rolled JSX with custom CSS. This approach has served the project well for domain-specific components but creates increasing cost for interactive overlays:

1. **Accessibility debt**: No focus trapping, keyboard navigation, ARIA attributes, or screen reader support in any modal, menu, or popover. Each new interactive component either inherits this gap or requires significant custom implementation.

2. **Behavioral reimplementation**: Every overlay re-implements open/close state, click-outside dismiss, escape handling, and positioning logic independently. This duplicates effort and creates inconsistency.

3. **Scaling cost**: As Litria adds features (command palette, settings panels, theme picker, node configuration dialogs), each requires the same behavioral boilerplate from scratch.

The existing approach works well for domain-specific components (canvas, editor, drawers, pills) where no library provides value. The problem is limited to interactive overlay primitives.

## Goals
1. Establish an accessibility baseline for all interactive overlay components (focus trap, keyboard nav, ARIA, portal rendering).
2. Preserve Litria's glass-morphic visual identity — all components must consume Litria design tokens and conform to `docs/ui-governance.md`.
3. Enable incremental adoption — no big-bang migration, components migrate one at a time.
4. Provide a clear, reusable decision framework for choosing between shadcn, Tailwind utilities, and hand-rolled CSS.
5. Keep existing hand-rolled CSS working unchanged.

## Non-Goals
1. Full Tailwind migration of all existing CSS files.
2. Theming system overhaul — `tokens.css` remains the authoritative source.
3. Replacing domain-specific components (canvas, editor, drawers, hover card).
4. Multi-theme support (light mode) — current dark glass-morphic is the only theme.
5. Adopting shadcn's default visual theme — Litria styling contract overrides everything.

## Proposed Architecture

### Layer Model

```
Layer 4: Existing BEM CSS (untouched, coexists indefinitely)
  └─ src/styles/*.css — 16 files, ~2,900 lines
  └─ Class-based selectors (.drawer-tab, .pill-notification, etc.)
  └─ No migration required. No sunset date.

Layer 3: shadcn Components (owned source, Litria-styled)
  └─ src/components/ui/*.jsx — generated by shadcn CLI, then customized
  └─ Radix primitives for behavior + Litria tokens for appearance
  └─ Only for interactive overlays (Dialog, Popover, DropdownMenu, etc.)

Layer 2: Tailwind Config (maps Litria tokens into TW theme)
  └─ tailwind.config.js — extends (does not replace) default theme
  └─ Maps --cm-* tokens to TW utility classes
  └─ Used by Layer 3 components and optionally by new Layer 4 code

Layer 1: Litria Design Tokens (authoritative, unchanged)
  └─ src/styles/tokens.css — CSS custom properties
  └─ Source of truth for colors, surfaces, glows, transitions
  └─ Referenced by all layers above
```

### Key Principle: Tokens Flow Down

`tokens.css` is the single source of truth. Tailwind config reads from it (via CSS variable references). shadcn components consume Tailwind utilities that resolve to Litria tokens. Existing CSS references tokens directly. No token is defined in two places.

### Directory Structure

```
src/
  components/
    ui/                    ← shadcn components (new)
      button.jsx
      dialog.jsx
      dropdown-menu.jsx
      popover.jsx
      context-menu.jsx
      alert-dialog.jsx
      command.jsx
    CanvasArea.jsx         ← existing (unchanged)
    EditorMonaco.jsx       ← existing (unchanged)
    ...
  styles/
    tokens.css             ← existing (unchanged, authoritative)
    reset.css              ← existing (reconcile with TW preflight)
    canvas.css             ← existing (unchanged)
    drawers.css            ← existing (unchanged)
    ...
  lib/
    utils.js               ← cn() helper (clsx + tailwind-merge)
```

## Decision Framework

When building or modifying a UI component, apply ADR-008's decision rubric:

```
Interactive overlay needing focus/keyboard/ARIA? → shadcn
Purely visual/layout? → Tailwind utilities or BEM CSS
Domain-specific (canvas, editor, coordinate math)? → Hand-roll
Deep custom animation (drawers, transforms)? → Hand-roll
In a protected zone (ADR-008)? → Hand-roll
```

## Styling Contract

Every shadcn component must:
1. Consume Litria design tokens from `tokens.css` (surfaces, borders, text colors).
2. Conform to the LED glow specification in `docs/ui-governance.md` Section 5.
3. Use glass-morphic surface treatment (semi-transparent backgrounds, backdrop-filter blur).
4. Apply `border-radius: 14px` for cards/dialogs, `999px` for pill-shaped elements.
5. Use Litria transition timing (`--cm-transition-fast: 150ms ease`).
6. Pass WCAG AA contrast ratios as documented in `docs/ui-governance.md` Section 7.

## Risks

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| Tailwind preflight conflicts with reset.css | Low | Low | Disable preflight or remove reset.css — both do the same thing |
| className bloat in JSX | Medium | Low | Use `cn()` utility for conditional classes. Consistent patterns reduce visual noise |
| Developer confusion (which approach to use) | Medium | Medium | Decision framework in ui-governance.md Section 11. ADR-008 protected zone registry |
| shadcn component styling drift from Litria identity | Low | High | Styling contract enforced at review time. All shadcn components must consume Litria tokens |
| Radix version conflicts or breaking changes | Low | Medium | Owned source code — pin versions, update on Litria's schedule |
